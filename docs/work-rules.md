# 作業規律

> やることの一覧は [Tasks.md](../Tasks.md)。憲章は [CHARTER.md](../CHARTER.md)。
> **ここは守るべき決まりだけを置く。着手前と、`[x]` を付ける前に読む。**
> Tasks.md 側には決まりを写さない。同じ問いに読み手が 2 つあると、片方だけ直して黙ってずれる。

## 行が備えるもの

1 行 1 作業。列は「**何を・なぜ・最小検証・Gate・状態**」。
**Gate は完了を証明するコマンドと、その出力が満たす条件**。機械か画像で合否が分かる形にする。
**Gate と再現が書けないものは、まだ課題ではない。** 先送りへ置く。

曖昧語は数値とキー名へ落とす（「速くなる」→「demo.md の初回描画が 800ms 以下」）。
ただし**根拠のない数値は曖昧より悪い。** 方針・権限・時間・個数・異常時の振る舞いは、
確定していなければ黙って埋めず、未確認と書くか `[~]` にする。測った数値か、起草中の数値かを明示する。

## 3 つのコマンド

| | 最小検証 | Gate | 再現 |
|---|---|---|---|
| 問い | この行の変更は効いたか | この行は完了か | どう見えるか |
| 返すもの | 合否 | 合否 | 現物 |

- **最小検証と Gate は着手前に同時に書き、`Tasks.lock.json` に封印する。** 両方とも落とせること
- **最小検証は、この行に対して赤くなれること。** Gate を薄めただけのものは書かない。赤は安いほうで先に確かめる
- 最小検証が緑で Gate が赤なら、絞りすぎ。**コードを直す同じ編集で最小検証を広げる**
- **行の Gate 欄にフル Gate のコマンドを書かない。** 行の Gate は行を証明するもの
- **再現は検査ではない。** 合否を持たない。1 コマンドで人を現物の前に立たせるだけ

## 3 つの run

| run | いつ | 予算 |
|---|---|---|
| **最小検証** | 毎回 | 秒 |
| **行の Gate + 未検査ぶん** | 行を閉じる前 | **2 分** |
| **フル**（`npm run test:ci`、`npm run test:local-only`、`npm run test:e2e`） | **push の直前だけ** | かかるだけ |

真ん中は毎周払うので、**人の注意力の閾値**として決める（1 分で切れる人もいる）。
フルは push ごとに 1 回なので対象外。**高くて完全な run は、手元を離れる直前に置く。**

## 検査済みの Skip

**Skip は導出する。主張しない。**「触っていない」は根拠ではない。認める根拠は強い順に:

1. **内容一致** —— その Gate が読む / 動かすファイルが、最後の緑と byte 一致
2. **影響を計算する道具** —— この repo にはまだ無い
3. **宣言されたレーン** —— まだ宣言していない（宣言したらここに書く）

3 つとも無ければ Skip は無い。suite を回し、どれかを作る行を起票する。
**Skip したものは行に書く**（push 前のフルがそれを反証する）。**push 前のフルは飛ばさない。**

## Gate を消すとき

**遅いことは理由にならない。間違っていることが理由になる。** 閉じた行の付随的な数値に固定されたもの /
到達できなくなった挙動のもの / 失敗箇所が分からない重複。**消す前に安い fixture へ載せ替える。**
削除は何を捕まえていたかと一緒に履歴へ残す。一度も赤くならない Gate は、仕事をしているから赤くならない。

## 並列化

**絞る前に並列化しない。** 効くのは、長い Gate を複製した木で裏に回す / 掃引・seed 違い / 独立した行の監査。
効かないのは、同一の木・同一ロック / 順序・状態依存の不具合 / 人が読まねばならない出力。
並列に回してよいレーンは行に書き残す。

## 完了の作法

**完了（`[x]`）の 4 条件** —— 4 つ揃うまで `[x]` にしない。同時に `Tasks.lock.json` の `passes` を `true` にする。

1. 行の Gate が最終 run で緑（`test.fail()` / xfail の裏に隠れていない）
2. 実画面・実値を**自分で**確認した（headless の pass を見た目の合格に読み替えない）
3. 1 コマンドの再現手段が行に書いてある
4. commit 済み

**人間の受け入れ確認は完了条件にしない。** ユーザに渡すのは好みや製品判断が要る問いだけ。

### `[x]` にする前に、別視点の検証を 1 回通す

Gate を書いた本人は完了を判定しない。別セッション / 別エージェント（[.claude/agents/gate-auditor.md](../.claude/agents/gate-auditor.md)）へ、**なぜ正しいかの説明を渡さずに**
行・差分・`Tasks.lock.json` の該当行・成果物だけを渡す。**攻めるのは差分ではなく、封印された Gate。**

1. **差分を戻して Gate を回す。赤くなること**（差分が test / tool だけの行では定義できない。理由を書いて 2 へ）
2. **挙動を壊して回す。各々で赤くなること。** 生き残った変異が穴の名前になる
3. **同じ変異で最小検証も赤くなること**
4. **assertion が実際に走ったか**（空マッチ・skip された fixture・0 件ループは静かに通る）
5. **再現コマンドを逐語で実行**し、成果物を自分の言葉で述べる

戻して緑なら、**コードより先に Gate を直す**。refactoring 案は **Gate 付きの行**にして積む。

## やらないこと

- 赤い Gate で commit / push する（無関係と言うなら、基準ブランチで再現することを先に示す）
- フル Gate で反復する / 絞る前に並列化する / 根拠なく Skip する / push 前のフルを飛ばす
- **封印した Gate を、やった結果に合わせて緩める**（amendment に理由を書く。`tools/check_tasks_lock.py` が止める）
- headless の pass を見た目の合格に読み替える
- 未承認の将来案をキューに混ぜる / 行を閉じるためだけに無関係な差分をまとめる
