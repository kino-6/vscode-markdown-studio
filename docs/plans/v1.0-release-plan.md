# v1.0 Release Plan

This plan refreshes GitHub issue #8 for the current v0.8.8 state. The original issue was useful as a release-readiness brainstorm, but several items are now complete or intentionally out of scope. v1.0 should be a clear public release, not a perfection pass.

Issue: https://github.com/kino-6/vscode-markdown-studio/issues/8

## Release Goal

Ship Markdown Studio v1.0 as a local-first VS Code extension that reliably previews Markdown, renders Mermaid/PlantUML/SVG, and exports polished PDFs with TOC/index/bookmarks.

The release should make a strong first impression:

- A new user understands the value in under 5 seconds.
- Install -> open Markdown -> Preview works without configuration.
- PDF export works after guided dependency setup.
- Failures degrade into visible messages, not blank output.
- Known Markdown dialect limits are documented.

## Current Baseline

Already complete or substantially covered:

- Preview and PDF export for CommonMark/GFM-style Markdown.
- Mermaid, PlantUML, inline SVG, KaTeX, footnotes, task lists, emoji, definition lists, superscript/subscript.
- PDF index, bookmarks, TOC handling, page breaks, configurable margins, output filename templates.
- Local-first dependency management for Corretto and Chromium.
- External-resource security modes and default whitelist.
- Proxy/custom CA support.
- Markdown corpus tooling with Preview/PDF/screenshot checks.
- 19-case local corpus coverage for common, adversarial, and docs-flavor Markdown inputs.
- Promoted example for math and local asset handling.
- Default PDF header/footer visibility fix with explicit text color.
- CI and tag-driven GitHub release workflow.
- Japanese package localization for commands/settings.

## v1.0 Scope

### P0 - Public Release Blockers

- [ ] README first-screen polish
  - [ ] Replace the current screenshot/GIF TODO with an actual visual asset or remove the placeholder.
  - [ ] Add a compact hero/value statement near the top.
  - [ ] Add a 3-step Quick Start: install, open Preview, export PDF.
  - [ ] Make the "Why Markdown Studio?" value proposition explicit.

- [ ] Marketplace readiness
  - [ ] Decide and set the real VS Code Marketplace `publisher` instead of `local`.
  - [ ] Confirm `icon/icon.png` exists and renders correctly at Marketplace sizes.
  - [ ] Confirm categories are valid VS Code Marketplace categories. Do not invent a `Markdown` category if VS Code does not support it.
  - [ ] Confirm keywords cover discovery: `markdown`, `preview`, `pdf`, `mermaid`, `plantuml`.
  - [ ] Package a local `.vsix` and install it in a clean Extension Development/VS Code profile.

- [ ] Zero-config first-run QA
  - [ ] Fresh install with no settings opens Markdown Preview.
  - [ ] Mermaid renders without external dependencies.
  - [ ] PlantUML either renders through bundled dependencies or shows a guided setup/error message.
  - [ ] PDF export either succeeds or clearly directs the user to `Markdown Studio: Setup Dependencies`.
  - [ ] No blank output for diagram syntax errors or missing dependencies.

- [ ] Release quality gate
  - [ ] `npm run test:ci`
  - [ ] `npm run test:preview-runtime`
  - [ ] `npm run benchmark:preview -- --repeat 1 --warmup 0`
  - [ ] `npm run benchmark:pdf -- --repeat 1 --warmup 0`
  - [ ] `npm run corpus:check -- --mode both --screenshots --repeat 1 --warmup 0`
  - [ ] `npm run package`

### P1 - High Value Before v1.0 If Cheap

- [ ] Demo/visual asset generation
  - [ ] Use existing `examples/demo.md` anchors and demo automation if it is stable enough.
  - [ ] Generate a short GIF or screenshot for README/Marketplace.
  - [ ] Keep the asset small enough for repository and Marketplace use.

- [ ] Release notes and changelog
  - [ ] Update `CHANGELOG.md` for v1.0.
  - [ ] Summarize the v0.8.x foundation: PDF navigation, themes, corpus validation, local assets/math example, header/footer visibility.
  - [ ] Document known limits without over-apologizing.

- [ ] Accessibility smoke
  - [ ] Keyboard can reach main Preview controls where applicable.
  - [ ] Copy buttons and diagram controls have accessible labels or readable titles.
  - [ ] Preview content remains readable in light/dark modes.
  - [ ] No obvious focus traps in the preview webview.

### P2 - Post-v1.0 Candidates

These are useful, but should not block v1.0:

- Obsidian-style wiki link resolution.
- GitHub alert block custom rendering.
- MDX/JSX semantic component support.
- Visual diff automation for screenshots/PDF pages.
- DOCX export.
- Watch/auto-export mode.
- Multi-file merge export.
- Presentation mode.
- Local semantic search/RAG/AI assistance.
- Workspace graph visualization.

## Suggested Work Branches

- `v1.0-readme-marketplace`: README, visual asset, publisher/category checks.
- `v1.0-first-run-qa`: clean install validation and any dependency/error-message fixes.
- `v1.0-release-notes`: CHANGELOG and release checklist finalization.
- `v1.0-accessibility-smoke`: preview keyboard/focus/labels pass.

## Definition Of Done

- P0 checklist is complete.
- Any P1 items included in v1.0 are documented and tested.
- `CHANGELOG.md` includes v1.0 notes.
- README no longer contains Marketplace TODO placeholders.
- A local `.vsix` installs and the basic Preview/PDF flow works in a clean profile.
- `v1.0.0` tag produces a GitHub Release with a VSIX artifact.
