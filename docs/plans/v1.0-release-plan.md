# v1.0 Release Plan

This plan refreshes GitHub issue #8 for the current v0.9.0 baseline. The issue is a useful release-readiness brainstorm, but several items are now complete, narrowed, or better treated as post-v1.0 product expansion.

Issue: https://github.com/kino-6/vscode-markdown-studio/issues/8

## Release Goal

Ship Markdown Studio v1.0 as a public, local-first VS Code extension that reliably previews Markdown, renders diagrams, and exports polished PDFs without sending document content to remote services.

The release should make a strong first impression:

- A new user understands the value in under 5 seconds.
- Install -> open Markdown -> Preview works without configuration.
- PDF export works after guided local dependency setup.
- Failures degrade into visible messages, not blank output.
- Known Markdown dialect limits are documented calmly.

## Current Baseline

Already complete or substantially covered as of v0.9.0:

- Preview and PDF export for CommonMark/GitHub-flavored Markdown plus common extensions.
- Mermaid, PlantUML, WaveDrom, inline SVG, KaTeX, footnotes, task lists, emoji, definition lists, superscript, and subscript.
- PDF index, bookmarks, TOC handling, page breaks, configurable margins, output filename templates, and header/footer color fixes.
- Preview current-tab/full-width commands and configurable Preview width.
- Local-first dependency management for Amazon Corretto and Playwright Chromium.
- External-resource modes with documented local-first posture and strict LocalOnly option.
- Proxy/custom CA support.
- Markdown corpus tooling with Preview/PDF/screenshot checks under `ignore/`.
- Tracked redistributable examples for WaveDrom and math/local assets.
- Demo render smoke check for `examples/demo.md` and committed demo PDF artifact.
- Preview runtime checks for copy behavior, TOC links, external links, zoom, theme switching, update-body, Mermaid, and WaveDrom.
- Performance work for batch PlantUML rendering, Mermaid caching, and visible-first Mermaid rendering.
- Japanese package localization for commands/settings.

## Package Slimming Notes

- v1.0-readiness packaging produced a 26.02 MB VSIX before package slimming.
- The generated `dist/extension.js.map` is now excluded; runtime only needs `dist/extension.js` and `dist/preview.js`.
- After source-map exclusion, `npm run package` produced a 25.13 MB VSIX with 650 files.
- Runtime now imports `playwright-core` directly; the higher-level `playwright` package stays in `devDependencies` for tests and scripts.
- Playwright Core is bundled into `dist/extension.js`, so `node_modules/playwright-core` is no longer shipped as hundreds of individual JS files.
- Playwright's Chromium downloader helper is bundled into `dist/oopDownloadBrowserMain.js`; the installer forks this helper during first-run setup.
- After Playwright Core bundling, `npm run package` produced a 22.48 MB VSIX with 53 files and no vsce file-count warning.

## Copy Bank

These drafts can be reused in README, Marketplace text, or release notes.

### One-Line Value Proposition

Markdown Studio is a local-first Markdown preview and PDF export extension with built-in Mermaid, PlantUML, WaveDrom, SVG, math, TOC, bookmarks, and security controls.

### Short Marketplace Description

Local-first Markdown preview and PDF export with diagrams, math, bookmarks, and external resources on a GitHub allowlist by default.

### Hero Draft

Local-first Markdown preview and PDF export for technical documents.

Render diagrams, math, code, local assets, TOCs, indexes, and PDF bookmarks from one VS Code workflow without sending document content to a remote renderer.

### Quick Start Draft

1. Open a Markdown file.
2. Run `Markdown Studio: Preview`.
3. Run `Markdown Studio: Export PDF` when the document is ready.

For PlantUML and PDF export dependencies, run `Markdown Studio: Setup Dependencies` if prompted.

### Why Markdown Studio Draft

- Local-first by default: Markdown, diagrams, syntax highlighting, math, and PDF export run on your machine.
- Technical-document ready: Mermaid, PlantUML, WaveDrom, SVG, code highlighting, KaTeX, TOC, PDF index, and bookmarks are integrated.
- Security-aware: external resources default to a GitHub allowlist and can be blocked or allowed explicitly.
- Practical PDF output: page formats, margins, headers/footers, filenames, TOC handling, page breaks, and bookmarks are configurable.

### Known Limits Draft

Markdown Studio targets CommonMark/GitHub-flavored Markdown plus documented extensions. Obsidian wiki links, GitHub alert blocks, MDX/JSX component semantics, and YAML front matter metadata are not interpreted as first-class document features in v1.0.
