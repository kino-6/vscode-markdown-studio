# v0.8.4 Cleanup Plan

## Goals

- Keep English as the primary UI and documentation language.
- Add a clear path for Japanese support instead of mixing Japanese and English in the same surface.
- Reduce duplicated configuration strings and defaults in TypeScript code.
- Move detailed documentation out of the README where it makes the landing page harder to scan.

## Findings

### Configuration

- Extension settings are declared in `package.json`, while runtime reads are scattered across `src/infra/config.ts`, `src/infra/networkConfig.ts`, and preview refresh handlers in `src/preview/webviewPanel.ts`.
- Defaults are repeated in `package.json` and TypeScript. VS Code still requires manifest settings in `package.json`, but TypeScript can at least share one local registry for keys and runtime defaults.
- The legacy `markdownStudio.security.blockExternalLinks` setting is still present for backward compatibility. It should remain deprecated, but its message should follow the primary English language policy.
- README contains a partial configuration table that is already out of sync with `package.json` (`export.pdfIndex.*`, `export.pdfToc.hidden`, and `export.diagramTimeout` are missing).

### Language

- `package.json` mixes English and Japanese in setting descriptions, enum descriptions, and deprecation messages.
- Production TypeScript comments include Japanese in several modules (`src/types/models.ts`, `src/infra/networkConfig.ts`, `src/export/*`, `src/infra/customCssLoader.ts`).
- Japanese sample content and tests are useful and should stay, because Japanese/CJK support is a product requirement rather than inconsistency.

### Docs

- README is doing too much: overview, full configuration reference, troubleshooting, dependency setup, roadmap, and known issues.
- README known issue for Japanese/CJK PDF bookmarks appears stale; tests indicate the UTF-16BE bookmark path is now covered.
- Example theme comments reference a removed `markdownStudio.style.customCssPath` setting and should point to `style.customCss`.

## Implementation Plan

1. Add a TypeScript settings registry with config keys and runtime defaults.
2. Refactor runtime config reads to use the registry instead of repeated string literals.
3. Convert extension manifest strings to VS Code package NLS keys.
4. Add English `package.nls.json` and Japanese `package.nls.ja.json`.
5. Translate production comments to English while preserving Japanese test/sample data.
6. Split detailed configuration and troubleshooting docs into `docs/configuration.md` and `docs/troubleshooting.md`.
7. Add a terminology glossary to keep English and Japanese wording consistent.
8. Refresh README to be a concise entry point and fix stale known issue/roadmap text.
9. Update changelog and package version for v0.8.4.
10. Run focused config tests, package/manifest checks, and TypeScript lint.

## Out of Scope

- Removing or renaming existing configuration keys.
- A full runtime i18n pass for every notification message.
- Changing behavior of PDF export, preview rendering, or dependency installation.
