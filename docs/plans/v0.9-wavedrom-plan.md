# v0.9 WaveDrom Support Plan

This plan covers adding WaveDrom timing-diagram support before the v1.0 release track. The user request used "webdrom"; this plan assumes the intended feature is WaveDrom / WaveJSON fenced-block rendering.

References:

- WaveDrom repository: https://github.com/wavedrom/wavedrom
- WaveDrom npm package: https://www.npmjs.com/package/wavedrom

## Release Goal

Ship v0.9.0 with local Preview and PDF export support for WaveDrom timing diagrams, matching the existing Mermaid/PlantUML/SVG diagram experience as closely as practical.

Minimum user-facing behavior:

- Markdown fenced blocks such as `wavedrom`, `wavejson`, and optionally `wavedrom-json` render as SVG timing diagrams.
- Preview and PDF export produce the same visible diagram.
- Invalid WaveJSON shows an inline error block instead of blank output.
- Diagram containers keep existing zoom/pan behavior where possible.
- Documentation, examples, and corpus checks cover the new syntax.

## Current Baseline

Existing diagram support:

- Mermaid uses extension-host placeholders and webview-side rendering in `media/preview.js`.
- PlantUML renders SVG in the extension host and embeds it into Markdown output.
- Raw SVG fenced blocks pass through inside `.diagram-container`.
- PDF export waits for preview-runtime diagram rendering before printing.
- The corpus pipeline can validate Preview, PDF, and screenshots for example Markdown files.

This means WaveDrom should reuse:

- `src/parser/scanFencedBlocks.ts` for fenced block discovery.
- `src/renderers/renderMarkdown.ts` for replacing source fences with rendered HTML.
- `.diagram-container` styling and zoom/pan runtime behavior.
- `scripts/corpus/runCorpusChecks.js` and examples for regression coverage.

## Recommended Architecture

### Preferred Path: Extension-Host SVG Rendering

Prefer rendering WaveDrom to SVG before Markdown is handed to the webview/PDF page, similar to PlantUML.

Why:

- Preview and PDF parity is simpler.
- PDF export does not need another asynchronous browser-side render wait.
- Error handling can be tested with unit tests.
- It keeps WaveDrom source out of live webview execution paths.

Risks to verify:

- The `wavedrom` npm API may expect browser globals or `WaveDrom.ProcessAll()`.
- The examples commonly use JavaScript object literal / JSON5-like syntax, not strict JSON.
- Rendering may require loading the default skin explicitly.

### Fallback Path: Webview-Side Rendering

If the Node-side API is awkward, add `wavedrom-host` placeholders and render in `media/preview.js`, similar to Mermaid.

Requirements for fallback:

- Bundle WaveDrom and its default skin through the existing webview build.
- Add `renderWaveDromBlocks()` beside `renderMermaidBlocks()`.
- Ensure PDF mode eagerly renders all WaveDrom blocks before print.
- Add cache and visible-first behavior only if rendering cost is noticeable.

## Scope

### P0 - Implementation Spike

- [ ] Confirm the current `wavedrom` package version and license.
- [ ] Verify whether WaveDrom can render SVG in Node without DOM shims.
- [ ] Verify accepted source syntax:
  - [ ] Strict JSON.
  - [ ] WaveJSON examples with unquoted keys.
  - [ ] Trailing commas and single quotes.
- [ ] Decide whether v0.9 supports only fenced blocks or also `<script type="WaveDrom">` HTML blocks.
- [ ] Decide the canonical fence labels:
  - [ ] `wavedrom`
  - [ ] `wavejson`
  - [ ] `wavedrom-json`

Recommended v0.9 decision: support fenced blocks only; leave raw HTML `<script type="WaveDrom">` support out of scope unless it falls out naturally.

### P0 - Parser And Renderer

- [ ] Add WaveDrom block kind to `FencedBlockKind`.
- [ ] Teach `scanFencedBlocks()` to detect WaveDrom fence aliases.
- [ ] Add `src/renderers/renderWaveDrom.ts`.
- [ ] Return a rendered SVG string or a structured error.
- [ ] Escape error output with the same pattern used for Mermaid/PlantUML errors.
- [ ] Preserve source-line padding so double-click source navigation remains stable.
- [ ] Add unit tests for:
  - [ ] Fence detection.
  - [ ] Successful WaveDrom placeholder/SVG replacement.
  - [ ] Invalid source error rendering.
  - [ ] Source content escaping.

### P0 - Preview And PDF Parity

- [ ] Ensure rendered WaveDrom SVG is wrapped in `.diagram-container`.
- [ ] Confirm zoom/pan initializes on WaveDrom diagrams.
- [ ] If webview-side rendering is used, add eager PDF-mode rendering and a print readiness wait.
- [ ] Run Preview runtime smoke tests with a WaveDrom fixture.
- [ ] Run PDF export smoke tests and inspect the generated PDF.

### P1 - Docs, Examples, And Corpus

- [ ] Add a small WaveDrom section to `examples/demo.md`.
- [ ] Add `examples/corpus-wavedrom.md` if the demo file is too broad for focused regression.
- [ ] Add a corpus case covering:
  - [ ] Basic signal wave.
  - [ ] Bus data labels.
  - [ ] Groups or nested signals if supported reliably.
  - [ ] Invalid WaveJSON fallback.
- [ ] Update README feature list and compatibility notes.
- [ ] Update `docs/troubleshooting.md` with a WaveDrom error row.
- [ ] Update `docs/third-party-notices.md` for the WaveDrom dependency.

### P1 - Release Prep

- [ ] Update `CHANGELOG.md` for v0.9.0.
- [ ] Bump package version from `0.8.8` to `0.9.0`.
- [ ] Run release quality checks:
  - [ ] `npm run test:ci`
  - [ ] `npm run test:preview-runtime`
  - [ ] `npm run benchmark:preview -- --repeat 1 --warmup 0`
  - [ ] `npm run benchmark:pdf -- --repeat 1 --warmup 0`
  - [ ] `npm run corpus:check -- --mode both --screenshots --repeat 1 --warmup 0`
  - [ ] `npm run package`

## Out Of Scope For v0.9

- Full VCD waveform viewing.
- WaveDrom editor UI.
- Remote `svg.wavedrom.com` rendering.
- Fetching remote WaveJSON files.
- Advanced dark-mode skin customization unless the default output is unreadable.
- MDX/React component support for WaveDrom.

## Open Questions

- Should the renderer accept JSON5-like WaveJSON, or should we initially require the syntax WaveDrom itself accepts?
- Should invalid diagrams appear as a warning in `RenderedMarkdown.errors` in addition to inline HTML?
- Should WaveDrom source be included in zoom/pan high-resolution rerender, or is SVG/CSS transform fallback enough for v0.9?
- Do we want `wavedrom` examples in the local corpus only, or promoted into `examples/` as a stable public use case?

## Definition Of Done

- A Markdown file with a `wavedrom` fence renders in Preview and PDF.
- Invalid WaveDrom content produces a visible inline error.
- Tests cover parser and renderer behavior.
- At least one tracked example demonstrates the feature.
- Corpus checks include at least one WaveDrom case.
- README and third-party notices mention WaveDrom.
- v0.9.0 can be packaged locally as a VSIX.
